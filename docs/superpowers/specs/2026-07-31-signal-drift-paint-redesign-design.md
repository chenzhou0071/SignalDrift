# 《信号漂流》玩法重构设计 —— 俯视角 2D 涂色对战

> 本文档取代《信号漂流》完整设计.md 中的玩法部分（原文档保留存档）。
> 原设计的后端三层架构、网关协议、大厅业务、房间生命周期管理全部继承，本文仅描述差异与新玩法全貌。

**世界观（设定补全）：** 玩家操控的"信号体"是悬浮的能量载体，向地面投射的"墨"实为**信号物质**——沉积之处染上所属方颜色、形成领地；信号体携带的信号能量（玩法上叫"墨量"）有限，站在己方信号物质上回收更快，被敌方物质覆盖的地面会干扰机体运转。黑洞扭曲弹道甚至湮灭信号，反射墙让信号弹镜面反弹——引力与反射，是这个世界残存的宇宙法则。

## 一、项目定位

- **性质**：后端求职作品（Golang 后端为核心展示面），兼顾可宣传、可现场演示
- **形式**：PC 端俯视角 2D 实时 1v1 涂色对战（Splatoon 内核 + 荒野乱斗式镜头表现）
- **客户端标准**："看得过去且有风格"——零美术资源，纯几何图形 + 粒子 + 辉光后处理的极简科幻风
- **人力假设**：以一人开发为基准，队友可选

### 技术栈（与原设计一致）

- 客户端：Unity2D（URP 2D Renderer），仅输入采集与画面表现，零战斗逻辑
- 后端：Golang，TCP 网关 + 大厅服务 + 房间战斗服务三层架构
- 存储：MySQL 持久化局外数据；对局数据仅存房间内存，局毕销毁
- 通信：自研二进制 TCP 协议（粘包分包、会话、限流、心跳、断线重连 Token）

## 二、核心对局规则

### 2.1 对局形式

- 1v1 实时对战，单局 3 分钟
- 每名玩家操控一个"信号体"（发光几何机体），WASD 移动 + 鼠标瞄准射击
- 无血量、无击杀、无复活：被敌方弹命中 = 减速 debuff 1.5 秒 + 脚下泼一小滩敌色

### 2.2 资源机制：墨量槽 + 地盘回墨

- 每名玩家一个墨量槽（上限 100），发射消耗、随时间回复
- 回复速度与移动速度由**脚下格子颜色**决定：

| 脚下地面 | 移动速度 | 回墨速度 |
|---|---|---|
| 己方色 | +30% | 2.0 倍 |
| 空白 | 基准 | 1.0 倍 |
| 敌方色 | -30% | 0.4 倍 |

- 设计意图：继承原设计"领土 = 资源"的经济内核，把数值结算转化为空间阵地博弈；回墨加成只看脚下不看全图占比，劣势方缩回己方区域即可满速回墨，保证翻盘火力

### 2.3 双弹道射击

发射瞬间锁定鼠标世界坐标，此后鼠标移动不影响已飞出的弹。每发弹获得**预定里程** = `min(鼠标到玩家距离, 该弹种最大射程)`；里程耗尽的那一刻，弹在哪就落在哪。

| | 左键·直射弹 | 右键·抛射弹 |
|---|---|---|
| 定位 | 铺色、压制、连发 | 越墙偷涂、远程开团 |
| 落点 | 初始方向 + 预定里程，途中事件改变实际落点 | 指哪落哪（确定性弹道） |
| 涂色 | 沿途窄墨线 + 终点小滩 | 落点大滩圆形溅射 |
| 墙体 | 被挡住，撞墙提前落地 | 无视，越墙飞行 |
| 黑洞 | 轨迹被引力弯曲，贴核心湮灭 | 无视 |
| 反射墙 | 镜面弹射 + 扣一截里程后继续飞 | 无视 |
| 命中玩家 | 减速 + 染色 | 落点圈内同效 |
| 消耗/速度 | 低耗、弹速快 | 高耗单发、飞行慢、落点有虚线预警圈 |

- 抛射的"下落"为纯表现：弹体飞行中先放大后缩小 + 落点预警圈；服务端无 Z 轴，仅按预定时间飞抵目标点结算
- 两种弹共用同一套"带剩余里程的 2D 弹体"框架，差异全由配置开关（是否碰墙/受引力/可反射）驱动

### 2.4 胜负判定（双判定）

- **时限判定**：3 分钟到时，普通地面格子的涂色占比高者胜，相等平局
- **即时胜利**：任一方占比 ≥ 75% 时，服务端广播"胜利倒计时开始"，双方屏幕显示 5 秒大倒计时；倒计时内落后方把占比压回 75% 以下即可打断；倒计时走完则立即终结对局
- 占比统计只计普通地面格子（墙、黑洞禁涂区不参与）

### 2.5 主塔（出生点）

- 双方地图两端各一座主塔：出生点 + 重连恢复点
- 塔周围一圈地面**永久为己方色且不可被覆盖**——劣势方永远拥有回墨安全区（原设计"无敌信号塔"的新形态）
- 永久色格计入涂色占比（双方对称、数量相等，不影响公平）

### 2.6 镜头与视野：全图固定镜头

- 地图世界 1280×720（16:9）恰好铺满一屏，镜头固定不动，双方全程明牌可见全部战况
- 无战争迷雾、无小地图、无镜头跟随——涂色玩法的爽点在"看着颜色蔓延"，全图镜头把它拉满，客户端也省掉整块镜头工作量
- 玩家直径 3 格在 1080p 上约 45 像素，操作目标清晰
- 宣传/观战视角 = 玩家视角，录屏零额外开发

### 2.7 终局结算流程（两种胜利方式及平局、断线判胜共用）

1. 服务端判定胜负 → 房间进入结算状态：停止接收输入、停止 Tick 模拟
2. 广播终局包：胜者、最终占比、全套对局统计
3. 客户端演出：胜方颜色以主塔为中心涌满全屏（纯表现）→ 结算面板：胜负 + 占比变化曲线 + 涂色/命中/反射/湮灭统计 + ELO 变动；平局演出为双色对半
4. 服务端：结算数据推入异步事件队列（写 ELO、对局历史入库），10 秒后或双方确认后销毁房间 Goroutine，玩家会话路由回大厅
5. 断线特例：一方超时未重连，在线方直接判胜，走同一条结算管线

## 三、地图与地形

### 3.1 两层坐标系

- **物理层（连续）**：玩家、弹体的位置/移动/碰撞全部用 float 世界坐标模拟
- **涂色层（离散）**：地面颜色存于格子矩阵，格子仅是"颜料的像素"
- 世界 1280×720 单位，一格 = 10 单位，即 128×72 = 9216 格
- 每格状态：`0 空白 / 1 玩家1色 / 2 玩家2色`（另有静态标记：墙格、禁涂格）
- 玩家碰撞半径 15 单位（直径 3 格）；直射弹半径 4 单位；抛射弹半径 6 单位
- "踩色判定" = 玩家中心点所在格子的颜色，每 Tick 一次数组访问

### 3.2 地形元素（单张对称地图）

1. **普通地面**：可涂色，胜负统计范围
2. **墙体**：挡直射弹、挡移动、不可涂色；围出中路要道与侧翼通道
3. **黑洞**（原设计保留）：固定引力点。引力圈内直射弹轨迹被拉弯，贴近核心湮灭；玩家进入引力圈被缓慢拖拽（可挣脱）；周围地面禁涂。置于地图中央
4. **反射墙**（原设计保留）：亮边墙，直射弹镜面弹射并扣固定里程；对移动等同普通墙。置于侧翼拐角

### 3.3 布局思路（左右对称）

两端主塔安全区 → 己方腹地 → 中央黑洞区 + 两条被墙分隔的侧翼通道 → 反射墙奖励弹道技巧。

### 3.4 地图配置化

地图 JSON 定义：尺寸、墙体矩形列表、黑洞坐标与引力参数、反射墙线段、主塔位置、禁涂区。服务端加载即用，新地图零代码。首发 1 张精心设计的地图。

## 四、涂色与溅射算法（服务端）

### 4.1 溅射浓度模型

抛射落地以落点为圆心、半径 60 单位（6 格）分三层按概率涂色：

| 层 | 半径范围 | 涂色概率 |
|---|---|---|
| 核心 | 0 ~ 60% | 100% |
| 过渡 | 60% ~ 85% | 50% |
| 边缘 | 85% ~ 100% | 20% |

- 随机数由服务端掷（服务端权威），结果经脏格子同步，全端一致
- 每格状态保持二值（是/不是某方颜色），无"半涂"中间态；浓淡观感由溅点疏密表达
- 遍历落点局部 13×13 格窗口即可，单次约改 100 格
- 墙格、禁涂格跳过；不做墙体遮挡判断（刻意简化）

### 4.2 直射弹涂色

- 每 Tick 将本帧飞过的线段膨胀为走廊涂色：中心 1 格 100%，两侧各 1 格 60%
- 终点小滩 = 半径 3 格的圆（同浓度模型）

## 五、网络同步方案

### 5.1 上行：指令流

- 客户端 30 次/秒发送输入指令：`{序列号, 移动方向向量, 开火标记, 弹种, 鼠标世界坐标}`
- 客户端永不上报自身位置；位置由服务端根据输入积分——防作弊根基
- 序列号用于幂等去重（继承原设计网关重复包过滤）

### 5.2 服务端 Tick（30Hz）帧内顺序

1. 消费输入队列 → 积分玩家位置（移速上限校验，含踩色加减速）
2. 弹体模拟：直射弹飞行 / 黑洞引力 / 反射 / 撞墙；抛射弹计时
3. 落地结算 → 溅射涂色 → 改动格子进入本帧脏格子集合
4. 墨量结算（按脚下颜色取倍率）、命中判定（减速 debuff）
5. 占比统计 + 胜负判定
6. 广播状态包

### 5.3 下行：实体状态与涂色格子分流

- **实体状态**：每 Tick 全量广播（2 玩家 + 场上弹体，单包 < 300 字节）
- **涂色格子**：仅发脏格子增量 `[格子索引 uint16 + 颜色]` 批量打包；一次溅射约 250 字节
- **全图快照**：仅入场 / 断线重连时下发，2bit/格位图 + RLE 压缩，约 1~2KB

### 5.4 客户端表现

- 状态插值渲染（100ms 插值缓冲）
- 一期：本机移动纯插值；二期进阶：客户端预测 + 服务端和解
- 涂色格子收到即刷贴图

### 5.5 服务端校验清单（防作弊）

移速上限 / 墨量充足才可开火 / 开火频率限制 / 射程合法性 / 所有判定服务端权威。

## 六、后端架构增量

### 6.1 原样保留

- 三层架构：TCP 网关（粘包分包/会话/多层限流/心跳/路由）→ 大厅 → 房间
- 大厅业务：账号注册登录（密码哈希）、ELO 段位、好友系统、ELO 匹配池（30 秒放宽分差、可取消）
- 内存异步事件队列：对局结束异步写 ELO / 对局历史 / 活跃度，战斗与 DB IO 隔离
- 房间生命周期：单房间独立 Goroutine、局毕回收；注册中心负载上报、最低负载分配、优雅排空缩容、过载保护
- 断线重连：30 秒缓冲、Token 恢复、全量快照下发（复用入场快照）、超时判负；离线方保留版图、不可操作
- 运维监控告警 + 分级日志；指标新增：每 Tick 脏格子数、涂色广播带宽

### 6.2 修改（仅房间服务内部）

- 内存模型：节点数组 → 涂色格子矩阵 + 玩家实体 + 弹体列表
- Tick 流程按 5.2 重写
- 广播模块新增脏格子增量编码 + 快照 RLE 压缩

### 6.3 砍掉

- 背包道具系统（破坏 1v1 公平性，CRUD 展示已有好友系统承担）
- 节点/信号塔产能经济（被墨量槽机制取代）

## 七、数据库

- `user`、`user_profile`（ELO）、`user_friend`：沿用原设计
- `user_bag`：删除
- `game_match_history` 字段替换为：

```sql
CREATE TABLE `game_match_history` (
  match_id BIGINT PRIMARY KEY AUTO_INCREMENT,
  uid BIGINT,
  result TINYINT COMMENT '1胜 0平 -1负',
  elo_change INT,
  final_coverage FLOAT COMMENT '最终涂色占比',
  painted_cells INT COMMENT '累计涂色格子数',
  straight_shots INT COMMENT '直射发射数',
  lob_shots INT COMMENT '抛射发射数',
  hits_on_enemy INT COMMENT '命中对方次数',
  blackhole_destroyed INT COMMENT '被黑洞湮灭弹数',
  reflect_cnt INT COMMENT '触发反射次数',
  match_duration INT COMMENT '对局时长(秒)',
  start_time DATETIME,
  end_time DATETIME
);
```

- 统计字段同时支撑赛后结算面板与个人战绩页

## 八、配置体系（全 JSON 驱动）

- `battle.json`：移速与踩色倍率、墨量（上限/回复/弹耗）、双弹道（射程/弹速/半径/反射里程损耗）、溅射三层概率、黑洞参数、命中 debuff、胜负阈值（75% / 5 秒）、对局时长、Tick 率
- `map_01.json`：地图几何（见 3.4）
- `server.json`：端口、限流阈值、心跳、重连窗口
- 热更不重启；房间开局时快照配置，局内不变以保公平

## 九、Bot 与演示方案

### 9.1 服务端 Bot

- Bot 为房间内虚拟玩家，走与真人完全相同的输入指令通道（每 Tick 注入指令），无任何后门
- 行为状态机（贪心策略）：
  - 涂色：寻找视野内最大空白/敌色区域，直射铺路，抛射砸密集空白区
  - 回墨：墨量 < 20% 折返最近己方色块
  - 对抗：玩家进入射程泼弹干扰，不追击
  - 避险：绕行黑洞引力圈
- 难度分级纯配置：瞄准误差角、反应延迟 Tick、决策间隔
- 入口：大厅"人机练习"直接开局；匹配超时 60 秒可选自动填 Bot（配置开关）

### 9.2 宣传素材生产线

- Bot vs Bot 模式 + 观战视角：挂机自动产出对局画面，录屏即宣传素材
- 赛后结算面板：占比曲线 + 涂色统计，宣传截图素材

### 9.3 面试演示包（最终交付形态）

1. 云端部署：docker-compose 一键起（网关+大厅+房间+MySQL）部署云服务器，下载客户端即可真联网对战
2. 单机兜底：localhost 起全套后端 + 人机对局，无网可演示
3. 监控大屏：Grafana 展示在线连接 / 房间数 / Tick 耗时 / 广播带宽

## 十、范围边界（一期不做）

- 客户端预测 + 服务端和解（二期进阶）
- 多地图、多人模式（2v2 及以上）、观战之外的回放系统
- 道具、皮肤、任何付费向系统
- 涂墙面 / 爬墙机制（俯视角下墙为纯障碍物，属机制取舍）
